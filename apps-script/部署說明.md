# 報到系統部署說明

> ⚠️ **順序很重要：先完成 Apps Script（第 1～4 步），再推送活動網頁（第 5 步）。**
> 網頁的報到功能會呼叫新版 Apps Script，如果反過來做，報到會失敗。

## 1. 貼上新程式碼

1. 打開報到試算表 →「擴充功能」→「Apps Script」。
2. 把 `Code.gs` 原本的內容**全部刪除**，貼上本資料夾 `Code.gs` 的內容，按儲存（Ctrl+S）。
3. 確認程式碼最上方兩個名稱和你的試算表一致：
   - `FORM_SHEET_NAME`：備用 Google 表單的回應工作表名稱（試算表下方分頁名稱，常見是「表單回應 1」）
   - `REG_SHEET_NAME`：新的「報到名單」，不用改，第 3 步會自動建立

## 2. 設定帳號密碼（指令碼屬性）

左側齒輪「專案設定」→ 最下方「指令碼屬性」→「新增指令碼屬性」，新增：

| 屬性 | 值 |
|---|---|
| `MITAKE_USERNAME` | 三竹帳號 |
| `MITAKE_PASSWORD` | 三竹密碼（**建議先到三竹後台改一組新密碼再填入**） |
| `STAFF_PIN` | 工作人員領取頁的密碼，自訂，建議 6 位數以上 |
| `MAX_CODES` | （選填）兌換碼上限，例如 `220`；不填預設 300 |

## 3. 執行初始設定與測試

1. 上方函式選單選 `setup` → 按「執行」（第一次會要求授權，請允許）。
   - 試算表會出現「報到名單」分頁。
   - 執行紀錄會顯示三個屬性是否都已設定。
2. 函式選單選 `testConnection` → 執行，確認執行紀錄裡有剩餘點數（不會發簡訊、不花點數）。

## 4. 更新觸發條件與部署

1. 左側「觸發條件」（鬧鐘圖示）：確認有一個 `onFormSubmit`、事件來源「試算表」、類型「提交表單時」。沒有的話新增一個。
2. 右上「部署」→「管理部署作業」→ 點現有部署旁的鉛筆 →「版本」選「**新版本**」→ 部署。
   - ⚠️ 一定要用「編輯現有部署」，**不要按「新增部署作業」**，否則網址會改變，活動網頁會連不到。
   - 「執行身分」維持「我」，「誰可以存取」維持「所有人」。

## 5. 推送活動網頁

在 GitHub Desktop 按 **Push origin**，約 1～2 分鐘後網站更新。

## 6. 活動前測試（建議用自己的手機實際走一次）

1. 從 LINE 點開活動網頁 → 報到 → 確認收到簡訊、畫面顯示兌換碼。
2. 用同一支手機、同樣姓名再報到一次 → 應顯示「歡迎回來」與相同兌換碼，**不會再發簡訊**。
3. 改用「我已經有兌換碼」輸入兌換碼 → 能進入闖關。
4. 用電腦打開工作人員領取頁（Apps Script 部署網址）→ 輸入 `STAFF_PIN` → 用兌換碼或手機末 3 碼搜尋 → 確認領取 → 再按一次應顯示「已領取」。
5. 測試完成後，到「報到名單」把測試資料整列刪除（全部刪除後兌換碼會從 SEM001 重新開始）。

## 備用 Google 表單

網頁報到失敗時，畫面會出現「改用備用報到表單」連結。請確認表單設定：

- 「設定 → 回覆」：**關閉**「限制只能回覆 1 次」、「收集電子郵件地址」選「回覆者輸入」或不收集、**關閉**「僅限組織內使用者」，避免要求登入。
- 手機題目加上回應驗證：「規則運算式 → 符合 → `^09\d{8}$`」。
- 「身分」選項的文字最好與網頁一致（學生／教職員／校外人士）。

## 安全說明

- 名稱結尾有底線的函式（如 `sendSms_`、`registerParticipant_`）外部無法呼叫，**請勿移除底線**。
- 工作人員領取頁需要 `STAFF_PIN`，手機號碼只顯示前 4 碼與末 3 碼。
- 活動結束後建議：更改三竹密碼、刪除 `STAFF_PIN`、依規定處理「報到名單」個資。
